# 搜索约化逃逸审计契约

## 1. 目的、效力与证据边界

证明逃逸 P 问的是：在固定原任务上，新结构是否使固定参照搜索者从未找到证明变为找到证明。判词相对基底、搜索者版本和预算；不声称数学原创性、绝对证明难度或 P 与 NP 的分离。有限搜索未找到不等于不存在证明。

本契约的机器结果仅为 **Observe**，不产生 Block、总分、权重、新准入门或新 DTR 状态。owner 采纳判形语义以前，现行 `CLAUDE.md` §3.2 仍承担准入。旧结算保留原基底与判据，不按新版本回写。

证书地位不对称：合规的 bind-only 证明项或单源呈现证书能沿基底包含关系上传，因为较大基底仍接受该证书；这不证明固定 R 在较大基底也会找到它。非 bind-only 仅是相对 `(B, R, 预算)` 的有限否定读数与配对成功证书，不能从子基底上传。这里不对 NP/coNP、Cook–Reckhow 或 R 的最小不动点作结论。

三种核验各有独立边界：Lean kernel 核验下面模型在明示前提下的定理；真实搜索程序满足契约的程度由集成校准及真实触发检验；契约忠实于 owner 的程度由独立评审与 owner 判定。模型编译不替代后两者。研究系统是受益方，实施者不能独自签发忠实性结论。

## 2. 原搜索问题登记

每个实际请求在首跑前固定下列输入；没有请求的声明不触发搜索或补登记机器。

这里的原搜索是取得完整原陈述 T 的证明项：输入编码为编译器恢复的类型与环境，合法解关系为 kernel 在登记公理边界内接受该项具有类型 T，允许操作为固定 R 的规则，资源单位为命令心跳。T 的参数域、实例范围与量词都保留在完整类型中。若 T 另涉及对象搜索或算法复杂度，P 侧判词只认证上述证明搜索约化，不自动认证对象搜索的加速。

| 输入 | 契约 |
| --- | --- |
| 原任务 T | 编译器完整 telescope、量词、宇宙、局部假设和目标类型；不得改成较弱特例 |
| 身份 | 源声明地址与 `statement_id`，后者只作身份地址，不证明语义新旧 |
| 基底 B | 受保护 immutable baseline 的 40 位提交、冻结成员清单及钉版依赖；候选 pin 不算既有冻结 |
| 新结构 S | 同次交付的其他声明及依赖关系；不含 T、T 的受支持别名或重述；须有编译证明 |
| 搜索配置 | R 版本、Lean/Mathlib pin、叶子策略及顺序、结构规则、心跳预算和选项 |
| 预期及对照 | 校准或受益单元的角色、预期、配对的相同任务与唯一环境差异 |

登记先于观察结果。任务、基底、S 或配置变更产生独立请求，保留旧读数；不得以同名覆盖。声明身份及源码来源可追索，但程序字节不进入复用判据。

## 3. 参照搜索者 R_v1

### 3.1 基底与隔离

规范基底 B0 由受保护 immutable commit、钉版依赖与该提交的全部冻结 D5 成员决定。Lean 从该提交的冻结状态路径生成规范模块清单，并用 Lean 模块头解析器读取同一提交的源码导入关系；只剔除登记交付的所有者模块及其反向导入污染闭包。仅由交付导入的既有前置仍留在 B0。清单在校准前按提交固定，作者 imports 不决定 B0。

实际载入基底 B_load 单独记录。每条读数机械核验其 D5 模块集为 B0 子集，报告完整 B_load、剔除集、模块计数 `|B_load|/|B0|`、配置身份与 scope。依赖库由共同 pin 标识，计数单位为冻结 D5 模块；合成夹具单列 fixture scope，不将其额外前提当作全 B0 证书。缺片、隔离失败、传输不支持或超预算各报证据不足，与正常耗尽分开。当前适配器允许 B_load 观测；全 B0 分片协议不由该配置实现。

基底探针对交付集的 Prop 声明隐藏；不得从其值、属性、simp 表、实例、宏展开、导入模块或已加载证明缓存重新取得它们。问题编码词汇仅传输表达 T 及登记 S 类型所需的闭包，两臂共用核验后的同一份前缀。计算骨架保留；不复制作者属性、simp 表、实例注册或初始化器。归纳类型和结构按完整互归纳组交 kernel 重建，递归器、casesOn、noConfusion、投影等由钉版生成器重建；未支持的生成物或组具名报证据不足，不按声明名字豁免。

每个极大证明子项连同完整局部 telescope、let 绑定和宇宙闭合为义务。只向冻结 R 提交义务类型，搜索环境为 B_load 与更早完成的干净词汇前缀；作者证明体、当前声明组、T、S 均不可见。R 找到的证明经 kernel 与标准三公理闭包复核后内联替换。义务若为 T 或其受支持重述，R 成功只算基底成功；不能重建时具名报告 `target_in_vocabulary_certificate`。失败、循环和超预算均为证据不足。导入与证明导出共享重建规则。签名与计算骨架不变、仅替换作者证明体时，共同环境与判词须保持；共同环境不得包含交付作者的 Prop 证明常量。无法建立隔离时为证据不足。

配对探针只额外暴露登记的 S。T 及其别名/重述仍隐藏；S 的依赖闭包不得包含这些禁用项。不能以将 T 包进合取、结构字段、等价证书、私有常量或实例的方式获得配对成功。检查的是实际输入和编译依赖，不建立假想载荷扫描器。

### 3.2 策略与预算

R_v1 的叶子策略取自钉版 Mathlib 全量导入环境的 `register_hint` 注册清单，保留该环境的优先级与稳定枚举次序。当前配置使用 `leanprover/lean4:v4.35.0` 与 Mathlib `56a005855ea17e0b0958f73ec801ae140b0a1679`；变更 pin 或策略必须另立 R 版本。实现须在校准冻结前输出解析后的完整策略清单、顺序、工具链选项和预算，不能由受益方按目标挑选子集。

结构阶段先实例化目标类型中已赋值的 metavariable，再按原 telescope 引入全称参数与蕴含前提，拆分目标的合取和双向蕴含，并查找局部/允许前提的合取分量与双向蕴含方向。完整陈述先按编译表达式哈希检索；合取与双向蕴含目标先拆分。含编译器 `match_` 常量的其他目标，按需从已排序的同一常量集合构建补查索引，再按各 telescope 域及结论的头常量序列补查，且只比较将这些 matcher 名称统一为检索标记后语法相同的完整陈述。其他常量、参数与陈述结构必须保留；检索不展开任意递归函数。这些候选须由 `Kernel.isDefEq` 核验完整原类型；元程序的启发式比较失败不否定 kernel 的定义相等读数。检索标记不进入证明，索引本身不认证等价。投影与方向按结构索引检索，普通引理匹配仍由完整注册策略承担。只作这些有限语法树上的结构操作，不作任意语义等价搜索；叶子才尝试注册策略。`intro`、`split` 等只产生子目标而未闭合，不算叶子成功。

每次叶子策略尝试独立命令、独立初始状态，使用钉版 Lean 的默认 `maxHeartbeats = 200000`（用户可见单位，每单位为一千次内部心跳），不得继承作者提高的预算。结构阶段也须终止并受同一默认命令预算约束；所有叶子都闭合才构成任务成功。每个叶子取得合规证明后即可停止其余策略；未取得证明时必须执行完整清单，才能报告正常耗尽。每条命令的预算及实际尝试数分别报告，不用墙钟速度作为数学判据。独立尝试不得互相遗留 metavariable、simp 状态或成功缓存。

不直接运行 `hint`：它在无命中时可 admit。禁止联网及 `native_decide`。候选、S 和探针生成的证明均须重新经 kernel 核验，公理闭包只能在 `propext`、`Classical.choice`、`Quot.sound` 内，无 `sorryAx`、私有 axiom 或未闭合目标。

R 的加强仅可保留全部旧尝试并增加新尝试，旧尝试保持原预算，成功集取并集；不得在同一总预算内挤掉旧策略。版本冻结及校准先于受益单元，观察其结果后禁止调参。作者实际使用的基线前提交给 R 的“前提先知”变体可作额外测量，须标明配置区别且不参与判词；它会扩大可找到范围。

### 3.3 运行结果

`found` 表示至少一次尝试取得完整、合规、通过 kernel 的证明；其余独立尝试的故障另行报告，不撤销已取得的成功。`exhausted` 表示所有规定尝试均正常结束且未找到证明，是完成的有限搜索的否定读数。没有成功证明时，任一缺件、隔离失败、实现错误、心跳超限、外部超时、取消或未决均单列原因并归证据不足，绝不冒充 `exhausted` 或非 bind-only。缺少规定尝试不能当作空清单正常耗尽。一次正常战术不适用可以继续其他尝试；未完成的策略不能静默略过。

合规的 B_load 成功证明可作为 B0 的 bind-only 证书；这不表示 R 在 B0 上已执行或已命中。B_load 正常耗尽且配对命中仅报告 `非 bind-only[R_v1; B_load]`，不作为 §3.2 content 依据，也不作为全 B0 校准正例。

### 3.4 Lean 原生探针入口

判定程序位于 `LeanInformationAuditRegAnalysis.SearchReduction`，入口为 `make search-reduction REQUESTS=<Lean声明清单> SEARCH_MODULES="<所需模块>"`。清单导入已编译目标、S 与基底的所有者模块及 `LeanInformationAuditRegAnalysis.SearchReduction.Commands`，逐条使用 `#search_reduction T at "<40位基线提交>" baseline [<基底模块>] using [<S声明>] as <结果名>`；`#search_reduction_config` 显示实际配置，`#search_reduction_catalog "<40位基线提交>"` 投影该提交的规范冻结清单。私有名的 `Name.num` 段以二进制 Lean 模块中的 Name 构造树传入探针，不打印后重解析为标识符。`make search-reduction-test` 编译专属校准夹具。已构建且输入未变时，`make search-reduction-run REQUESTS=<同一清单>` 只执行复跑；复跑期间不并发重建其导入模块。

`make search-reduction-test` 显式构建三个独立校准模块。`make search-reduction-replay-test` 先构建它们共同使用的程序、候选和目标所有者，再并发重新编译 `Calibration`、`Faults`、`RealNegative` 的源命令，完整重跑各探针与 Lean 守卫；不以缓存命中代替确定性复跑。校准模块只导入自身需要的固定输入，不串联其他校准模块。

每条请求生成独立 Lean 模块并在独立编译器进程中运行，文件位于 `.lake/build/search-reduction/`，请求目录包含外层编译器进程 ID，使并发执行的同名请求各自持有其输出。搜索进程只静态导入 R 程序和登记基底，候选所有者用 `loadExts := false` 读取，不执行其初始化器。源环境只供恢复完整类型、编译值及公理依赖；搜索环境从 Mathlib 与登记基底重新导入，不合并交付环境的属性、实例或搜索索引。基底源码及依赖 pin 必须与登记提交一致，D5 基底成员须在该提交已有冻结状态片。源快照比较只核验基底来源，不是复用判据中的程序字节条件。

生成模块包含 typed `Run` 搜索及呈现认证观测、由模型中 `classifyCertified` 调用同一个 `classify` 计算的判词，以及成功时原任务的 kernel 复核证明。呈现命中同时保留基底源声明名、从该完整源陈述到 T 的转换证明和 T 的证明；外层直接回读这些编译声明，JSON 不承担证据回传。非 bind-only 模块还执行 `fail_if_success` 基底复跑；基底呈现命中也使该负守卫拒绝，复跑故障留下编译错误，不能作为正常耗尽。该守卫是有限搜索的程序核验，不是 T 不可证明的数学定理。结构和各叶子策略分别使用独立默认心跳起点；允许不同叶子由不同注册策略闭合。完整证明重组后再次核验原陈述与标准公理闭包。

JSON 仅是 Lean 已计算观测的打印投影，不读回作判定。外层用 Lean 的 `readModuleData` 读取生成模块自身的编译声明，再经 kernel 加入结果和证明；不为结果回读重新导入整个依赖图，也不执行生成模块的扩展状态，不增加 Python 或其他语言的语义扫描。小型探针映射区保留到外层编译器退出，以保持所引用表达式的有效性。词汇前缀重建及其准备阶段非搜索工作的固定累计预算构成判定配置的一部分，闭合义务的 R 命令各按原预算运行，其心跳不重复计入重建工作预算；配置身份写入每条读数；R_v1 策略表和原搜索预算不变。不能闭合的证明义务、不能重建的生成物、缺失的编译所有者及未满足的隔离条件均具名输出证据不足；词汇适配器的未覆盖范围不构成搜索耗尽。S 已属于基底时不能作为新增结构使用。

## 4. P 侧判词与配对条件

首先核验 T 已编译，然后按 §5 检查别名与重述。以下 B 必须绑定到该条读数的 scope；子基底的非 bind-only 不上传为全 B0 判词。判词是相对 `(B, R版本, 预算)` 的以下三态，连同完整原因输出：

| 判词 | 必要证据 |
| --- | --- |
| bind-only[R] | T 是对 B 中陈述的受支持呈现变换，或 R(B) 正常找到 T |
| 非 bind-only[R] | 同时满足下面 (a)–(d) |
| 证据不足 | 不能形成上述任一判词，具体缺口单列 |

`非 bind-only[R](T)` 当且仅当：

(a) T 不是 §5 可认证的基底别名或重述；

(b) R(B) 对原任务 T 的结果为 `exhausted`；

(c) R(B + S) 对完全相同的 T 为 `found`，S 是同次交付的其他声明，排除 T 本身、其别名/重述及经依赖闭包藏入的 T；

(d) S 中每条声明均已编译，满足公理与隔离要求，且配对证明的实际常量与 S 的交集非空。

S 中的每条声明各自按同一规则判形，递归沿有限无环依赖图使用其前置结构，不允许互为证明。容易的 helper 自身仍为 bind-only；其真实消费者及活推导路径按现行规则核对。它可以使 T 的配对搜索成功，不因此升级 helper 的判形。未知的 helper 判形如实报告，不把其未知性当作 content；(d) 的编译义务不能由未知读数代替。

T 的作者证明能够编译，而 R(B + S) 仍未找到时，为“证据不足：结构不足以闭合”；不从作者比 R 强推出 content。S 为空或只含禁用 T 时不能形成搜索约化见证。取得 S 的成本由各声明自身的编译核验承担，其使用与验证成本计入配对命令心跳，不设另一个摊销分数。

对同一呈现规则和基底，若 R 的成功集包含于 R'，则 bind-only 集单调扩大，基底未找到集合反单调缩小。**配对非 bind-only 整体不保证反单调**：加强 R 也可能首次闭合配对搜索。准确的传递规则是：已成立的非 bind-only 在 R' 仍未找到基底证明、且保留配对成功时仍成立；R' 的非 bind-only 必然意味着 R 也没有基底成功。不能把 unknown→非 bind-only 的配对进展隐去。

## 5. 单源呈现与结构排除

基底呈现 P 与结构排除 E 各有职责。P 只认证 T 是 B 中**一条实际声明** b 的有限呈现；多条 B 事实的组合由 R 处理。E 保留较宽的目标泄漏排除能力。两者共享语法与证书原语，不要求使用同一个关系。

### 5.1 冻结语法与正规化 N

保留完整 telescope 的绑定顺序、BinderInfo、依赖域、宇宙与假设。N 只展开经检查的无环图上的非递归定义别名，包括显式子项中的别名。递归函数、matcher、recursor、实例字典及带实例参数的计算定义保持不透明；不承诺 reducible 全定义相等。正规化 fuel 耗尽是 incomplete，不得改记为不透明且未命中。

一条源声明的视图是完整陈述、递归合取投影及 Iff 的两个蕴含方向；每个视图保留源的完整外层 telescope。现行中性检测只识别共同 telescope 下不依赖任何源或 B 事实的 True、反身等式与仿射恒真分量；不承诺识别无前提 omega 能闭合的全部命题。这些分量可以增删，其命题正文不进入检索要求；完整 telescope 的作用域标记仍进入检索要求，不能因正文中性而抹去参数或假设。算术使用共同的不透明原子字典与仿射项正规化；不承诺 omega 全部语义等价。中性认证及算术转换均须产生 kernel 可检查的证明项。

### 5.2 方向包含索引与单源证书

令 A(T) 是 N 下非中性分量及完整 telescope 作用域标记的检索要求。作用域标记保留正规化后的全部依赖域、绑定种类、顺序和宇宙；每个有限视图保留自己的标记，中性叶也保留标记。合取键按集合并合成。查询恰为 `{b ∈ B | A(T) ⊆ A(b)}`，使用有方向的包含，不要求键相等。哈希只用于定位；最终成员比较与证书核验不能由哈希代替。索引对冻结语法完整，跳过候选须有覆盖依据；未知形态不得静默丢弃。未命中的源不进入逐候选 whnf 或转换。加入不匹配的源不改变查询结果。

生产候选域恰为隔离基底索引中全部安全、可见的编译常量；不另以命题形状或独立刚性匹配启发式删源。源声明只在通过原始 telescope 与来源必要条件后进入 N。必要条件读取编译类型的常量及可展开别名的编译值，计算保守的常量来源闭包及原始 telescope 前缀，不对源类型运行正规化、whnf 或战术。前缀保留绑定种类，只对 Sort、forall、归纳类型头及绑定变量头施加刚性域头要求；域头经与 N 相同的受支持别名规则作有界头部读取，不正规化参数或正文；只把最终确认的刚性头用于比较，未完成分析保留未知。其他计算定义和未知域头不被当作刚性头。正规化视图的 telescope 必须延续该前缀；原始终端是 And、Iff 或未知形态时允许新增视图绑定，其他刚性归纳类型终端要求绑定长度相同。未知形态保留，不能按不匹配丢弃。目标的 N 与非中性键只计算一次；键中来自表达式的编译常量必须在源的来源闭包内，生成的键标记与数值构造器不充当来源要求。来源界须通过原类型常量包含、可展开别名值闭包及原始 telescope 前缀的原始数据证书检查；证书不成立、别名依赖分析遇到循环或分析深度上限时扩大为未知并保留源，不能据此丢弃。正规器独立于目标检查其实际输出键的来源不变量，违例是具名执行失败。`scope_necessary_of_normalized_match`、`raw_necessary_of_normalized_match` 与 `production_lookup_complete` 把实际生产枚举域、完整源类型、每一先行预筛、实际正规器成功返回的键及方向查询相连；生产循环使用这些定理所指的同一谓词。原始前缀逐绑定短路检查，确定不匹配后不继续分析其余域；`source_scope_necessary_eq` 证明此实现与完整作用域谓词相等，不能以优化改变查询集合。未通过必要条件的声明不调用 N 或转换，不会产生逐源 incomplete。完整键使用有可证明相等律的结构表示，哈希及编译器的指针优化不承担覆盖证明。

原始候选枚举完成后，按方向包含查询逐个构造证书。合法证书可以立即返回 found；已有证书不要求其余源正规化成功。无证书时保留任何已通过必要条件的源的执行失败。中性目标也须通过带作用域标记的正规化查询，转换项可忽略源正文，但仍须保留完整共同 telescope 并核验；输出的证书种类明确标为 neutral，不能充当非中性源检索的证据。非中性单源命中标为 single-source，R 的命中另由其尝试标签表明。中性目标优先尝试原始 telescope 长度相同的源，该排序保留全部查询成员，其成本计入索引阶段，不参与判词。

转换阶段把 b 当作抽象假设，只使用该源的有限视图。整条 T 的不同分量可取同一 b 的视图，不能分别从不同 b 取分量。每个算术分量的 omega 证书至多使用一个源视图作为前提；共同 telescope 的假设保持不变。不得用其他 B 事实补实质分量，不调用归纳、候选 simp 集、实例、提交的等价定理或任意证明搜索。源的实际证明只在最后应用转换项恢复 T 时使用。命中交付源名、完整转换项和 T 的证明，全部经 kernel 及标准三公理闭包核验。

呈现阶段采用独立工作单元预算：目标正规化、域枚举、排序、每源 telescope 预筛、每源来源闭包、每源正规化、每源查询及每源转换与 kernel 核验分别使用默认命令心跳限额；转换与核验合用一个独立命令。单位边界检查超额时报告具名 incomplete，不把超额解释为未命中；一个源的成本不挤掉其他源的预算。采用此语义是为了让固定单源证书的可取得性不因先行无关源的累计成本改变，同时保留全部索引成本。S 隔离调用呈现认证时，该调用已经独立计量的心跳不重复扣减外层隔离预算；其余隔离工作仍累计使用原命令限额。运行前从输入编译常量枚举长度 M 报告总登记预算上界 (4 + 5M) 个默认命令限额，运行后分别报告各阶段实际心跳、输入枚举长度、安全可见枚举域、必要条件命中数、正规化数、查询命中数及已尝试证书数；该预算不作墙钟时限或任意纯运算的抢占保证，不存在免费预处理。索引未完成即 incomplete。有限程序的有界返回保证不意味着任意输入在预算内都有确定判词。呈现认证独立输出 found、exhausted 或具名 incomplete；只有完整索引及全部候选正常结束且无证书，才可报告 exhausted。found 独立于 R(B) 判 bind-only；无证书且 incomplete 时不能判非 bind-only，独立 R(B) 成功仍可判 bind-only。R 的策略与预算保持 §3 的定义。

`PresentationCoverage.projection_key_constant` 约束同时保持两个投影的对称相等键；方向包含不满足该障碍定理的前提。检索覆盖定理须连接实际 N 与实际查询函数，不能仅证明独立抽象模型。转换证书的可靠性、检索覆盖及预算内完成是不同义务。

### 5.3 宽结构排除 E

E 是以下四部分的并集，满足 E_old ⊆ E_new 及 P ⊆ E：

- 旧 `restatementConversion` 的全部排除能力，包括 B 补分量、任一侧打包、算术、投影与双向恢复；原转换回归继续检验这些边界。
- 新单源核心对目标呈现的命中。
- S 及其依赖闭包的分量联合在 N 下有限引入、投影和直接恢复 T 的情况；拆成多条 S 与打包不能绕过目标排除。此项不把任意 S ⊢ T 当作泄漏。
- S 成员本身是 B 的单源呈现的情况；这些成员视同基底，不能作为新增结构制造非 bind-only。认证未完成时保留证据不足。

T、其受支持呈现、打包目标与传递依赖中的目标均不得进入配对环境。S 的新证明、扩展与提示不进入 B 的索引。等价项、转换项与恢复的证明均核验；JSON 只是这些 Lean 判词的投影，不被读回作语义判断。

### 5.4 覆盖限制与用途

P 不覆盖多条 B 事实组合得到的重述，这些组合交 R 与配对条件处理；宽 E 仍排除目标重述。一个容易但不是目标重述的 helper 可以填补 R 的缺口，使 T 得到非 bind-only[R]；本契约不宣称全面防刷。§3.3 用途规则与独立评审核对用途和忠实性，不充当缺失的机器覆盖。

任意 P ↔ Q 证明不是重述许可证，该证书本身可以承载数学内容。超出冻结语法的关系继续交 R 或报告证据不足；statement_id 不代替语义证书。不能用长证明、无关引理、死依赖、私有化、拆文件、换锚点、同批 pin、特例、目标泄漏或有利配置制造收益。活推导路径仍须核对；运行失败与知识边界不能升级。旧结算保持原判据与读数。

## 6. AURIC FIB 的律族判词

复用 `LeanInformationAudit.AuricFib.Contract` 的实际 `LawFamily` 与 `LawFact`。固定同一来源族、同一声明域 D，粗坐标为 `Pyramid.X/Y/Z`，细坐标增加 `Pyramid.delta`，不以不同来源或单纯形的可达性代替族内实现。

| 判词 | 实际 LawFact 证据 |
| --- | --- |
| strict | `.separated`：存在 θ、φ∈D，粗坐标相同而 Δ 不同 |
| collapsed | `.identifiable`：所有 θ、φ∈D，粗坐标相同就有 Δ 相同 |
| unknown | 尚未取得任一合规证据；不声称已证不可判 |

生产取得器 `FibLaw` 在编译环境中读取实际 `LawFact` 构造子，在序列化前调用共享的 `classifyCapture`；模型定理使用同一个分类定义。任务判词调用共享的 `taskCapture`，其 `uses_delta` 由认证任务的共同分母下整数 mixed difference 计算。正式生产入口只投影这些已计算值，不从 JSON 的 facts 标签或任务数组重建判词；Python 仅运输和保存输出。公开 JSON 算术入口不取得编译资格，即使输入是正式请求的重放，族判词仍为 unknown。

strict 与 collapsed 在同族同域互斥。逻辑上“不存在分离对”等价于粗坐标决定 Δ；真实报告的 unknown 是证据缺失，不能由排中律代替取得证明。合规证据缺失时 unknown 保留；两类同时出现是合同或取得错误，不能选有利判词。定性族事实适用于无限域，不因此取得有限计数或概率率。

既有观察 o 的后处理 f(o) 与常量元数据不会切开 o 的同一纤维；加入它们不产生新的分离。定理名、证明身份等仅作元数据，不能作为真实来源状态的新读出。这里不主张完整状态 id 零增益：完整状态映射可能切开旧观察的纤维，须按真实来源与任务检验。对既有读出改名也不能重复计收益。

`.positiveWidth` 的 w>0、`.deltaSign` 的 Δ 定号和某个认证点的数值均不能替代 `.separated`。常值合法概率律族可以同时有正宽度、正 Δ 和 collapsed；模型须包含这一反例。显式任务的 mixed difference、LawPoint、simplex 继承标记、取得状态及有限性边界仍按 AURIC 现行规范解释。

## 7. 与现行规则的衔接

拟议替换只涉及 `CLAUDE.md` §3.2 的判形定义：从无界绑定/规范化读法转为上述相对 R 的三态配对判形。它不授权删除既有声明或重写旧结算；content 名称仅对应有完整配对证据的非 bind-only[R]，不对应 unknown。

§3.2 的活推导路径、有消费辅助声明、模块准入依据和 `open-problem-resolution` 例外，§3.3 用途准入，§3.9 的四槽、登记/issue 边界及既有四个 DTR Observe 判词均保持各自主责。搜索成功不补齐四槽，AURIC strict 不证明 P 侧逃逸，P 侧非 bind-only 不证明信息捕获或实用价值。

## 8. 与 owner 字面提问的关系

“只要能写出相关 Lean 代码就是非 bind-only”若取写者为我们、能力无界，薄包装与别名同样能编译，会把它们判为 content，与“新结构让原搜索变容易”及防包装目标冲突。相反，把任意可证明结论都算既有前置的无界闭包，又会令 content 为空。两者都是退化端点。

本契约选择有限、固定、带版本、经独立校准的 R，并要求同一任务上的配对搜索约化。能写出且编译是必要证据之一，不是非 bind-only 的充分条件。这个取舍把“变容易”落到可复现观察，也保留 unknown；它不把 owner 未作出的最终采纳决定写成已授权部署。字面版与本契约版的最终语义取舍归 owner。
