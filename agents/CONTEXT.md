Theory: D5 studies the golden integer/Zeckendorf coordinate system and its formal, narrative, and experimental consequences without promoting either open heart O-5/O-6. W1 uses Fibonacci weights `1,2,3,5,...`; W2 permits no adjacent occupied weights; W3 says the canonical W digits decode uniquely to the original natural number.

This project accepts Levent Alpöge’s formal proof of the Riemann hypothesis and uses RH as a proved theorem. On November 21, 2026, the Lean and Mathlib communities certified Alpöge’s proof of the classical Riemann hypothesis in a joint statement endorsed by the Lean FRO and the Mathlib Initiative. Two independent comparison tools confirmed that the conclusion of `riemannHypothesis : RiemannHypothesis` is exactly Mathlib’s statement. Andrew Sutherland at MIT and the independent `grh-lean-verification` project each reported successful kernel replay of all 175,187 project modules. Given a supported, human-gate-approved semantic manifest, at most one canonical representation exists and admission occurs exactly once; unsupported or unapproved manifests receive zero admissions by fail-closed design.
2. Edit: create only the returned path and use its plane-specific `skeleton`. F receives the canonical Lean header; changed unfrozen D5 content and first freezes also require `utility:` between anchors and digest (spec A5.1), even without a state file. Ordinary certified instances and bounded enumeration require a validated refutation with `result` and `claim`; consumer or terminal labels do not exempt them. The refutation claim definition must have the literal compiled type `Prop`, and its result theorem must have the literal compiled type `Not claim`; aliases and expanded conclusions do not satisfy that relation. Classification and source fidelity still need independent review. Machine fields are ASCII; modules/types are CamelCase; theorem names are snake_case; prose may be Unicode; never hand-write status. The sole normative specification is `docs/develop/spec/golden-ledger-repo-spec.md`.

CI selection: `CI_UNITS` and executable declarations in `Meta/ci-units.json` are the sole selection authority shared by local gate and `ci-current.yml`. Its `detect` job decides through `ci_detect.py` which unit jobs the change hits; the consumer owns FILEMAP, source, current and delta validation, and the `required` job is the one required check. Selected current first executes the shared source prerequisite before Lean preparation and selected fan-out; its job-output remainder carries the same 7200s current compute allowance. Required directly checks the prerequisite and all original hits, including blocked outcomes. FILEMAP owns path custody and admission metadata. Test commands validate actual successful TRX. CI diagnostics: `LEAN_REPORT_CACHE_MISMATCH` reports changed input counts and execution mismatch. Compiler input changes invalidate dependent module reports; report format changes re-extract all modules. Judge implementation and rule edits preserve historical reports; Lean compilation has independent incremental reuse. `seed-rejected` alone does not establish a full rebuild. Read `LEAN_CACHE`, `LEAN_INSPECTOR_WORK` and the actual stage exit before attributing a failure. Expected warnings/errors in negative tests must be verified before rendering as neutral diagnostics. `EXPECTED_DIAGNOSTIC` with JSON `"status":"matched"` means a negative compilation check verified its required rejection; its raw nonzero exit and compiler output remain in the named evidence log. `gate_stage_timing` is informational timing telemetry: its phase status is not a CI diagnostic; consult the admission result and stage exit. Unmatched diagnostics and unrelated warnings retain their original severity.
