Given a supported, human-gate-approved semantic manifest, at most one canonical representation exists and admission occurs exactly once; unsupported or unapproved manifests receive zero admissions by fail-closed design.
2. Edit: create only the returned path and use its plane-specific `skeleton`. F receives the canonical Lean header; changed unfrozen D5 content and first freezes also require `utility:` between anchors and digest (spec A5.1), even without a state file. Ordinary certified instances and bounded enumeration require a validated refutation with `result` and `claim`; consumer or terminal labels do not exempt them. A companion theorem may turn a positive/existential counterexample into `Not claim`. Classification and source fidelity still need independent review. Machine fields are ASCII; modules/types are CamelCase; theorem names are snake_case; prose may be Unicode; never hand-write status. The sole normative specification is `docs/develop/spec/golden-ledger-repo-spec.md`.
3. Check: choose local scope explicitly; bare `make preflight` prints choices and fails before work. For harness iteration use `make preflight MODE=fast` (quick .NET structure tests, no Lean/admission proof) plus targeted tests; for Lean iteration use targeted `make lean`. For complete baseline-to-worktree validation use `make preflight MODE=push BASE=<40-hex-commit-sha>`; this includes committed, staged, unstaged, untracked and deleted inputs. No-resource documentation deltas can avoid .NET work. For integration use `make preflight MODE=pr BASE=<40-hex-commit-sha>` from a clean committed source; it checks an isolated merge-tree candidate. Use `make preflight MODE=full` only for deliberate whole-current-tree diagnostics; it retains normal caches and incremental producers. fast/full reject BASE and push ranges; push requires an existing nonzero immutable BASE and accepts only matching complete CI_PUSH_BEFORE/AFTER copies. Shared modes reject inherited native push events, reusable workflow candidate inputs and stale CANDIDATE_SHA. CI runs `make -C tools ci-build` once, then engineering and current independently. The shared runner binds retained build/TRX evidence and current reports to the same candidate and build round; `make delta BASE=<40-hex-commit-sha>` checks cross-tree constraints using those results. The .NET rule engine never invokes Lean. Stage summaries preserve raw exits; make reports success or recipe failure.
4. Deposit: `make deposit ATOM_ID=... GID=... BASE=...` resolves BASE to an immutable SHA for `deposit-header-check`. Only baseline-frozen membership earns historical exemption. The current Lean report (including typed refutation evidence when required) is checked before freeze; exact designated-result atom coverage is required at final FirstFreeze admission. A candidate-only state pin does not skip the utility precheck.

CI resource selection: `Meta/FILEMAP.toml` and `Meta/ci-resources.json` select build roots, registered references, complete test projects and current checks. A compiled test reference does not request execution. Selected tests run without filters or supply validated original successful TRX retained under `build/ci`. Delta consumes required stages from the same candidate and build round, retains baseline CI project registration/topology constraints and validates successful coverage for the selected tests; it never reruns common work. No-resource stages report `not-required`; malformed or incomplete plans fail. Explicit engineering/current without a resource plan retain their complete obligations.
