## 构建:走 serial-lean,禁裸 make lean

    bash tools/scripts/agent/serial-lean.sh <本树绝对路径>

Lake 5.0.0 **没有 job 数旋钮**(`-j` 表示 `--json`,
`lake build --help` 无 job/parallel 选项),`LEAN_NUM_THREADS` 只限单进程内线程、
**不限 lake 拉起几个 lean 进程**。串行入口限制构建进程并发,以控制内存占用。

资源读数(采集时点:2026-09-11;八核、16 GB 宿主):裸 `make lean` 单席配置同时运行
约 7 个 lean 进程、各占 0.8–3.4 GB,内存空闲比例 25%。`serial-lean` 三席并发配置
完成完整门链,40 个采样点的最低内存空闲比例 55%、低内存守卫终止次数 0。

## 构建被终止后:先核归属,再重跑

启动构建时,通过宿主后台作业机制保留本任务创建的进程句柄;需要整组管理时,
由本任务用 `start_new_session` 等机制创建独立进程组并持有其句柄,记录 pid/pgid。
重跑前通过这些启动记录与句柄核对该构建派生的 lake/lean;只终止本任务自己创建、
且仍能由所持 pid/进程组句柄或宿主作业句柄确认归属的进程。

本树 cwd 只用于列出候选,不单独构成终止依据;多个任务可以共用同一棵树。
命令名、参数、路径模式和「非本引擎后代」都不能证明归属,不得据此批量终止。
无法证明归属的进程不动,只报告;尚未排除同树重复构建时不重跑。

清完用 `memory_pressure` 的 `free percentage` 确认真的降下来了再重跑。
**不要用 `ps -eo rss=` 求和判内存**:该读数不含完整的 compressor / wired / 文件缓存占用。
macOS 内存读数中,5.03 GB RSS 总量对应 25% 内存空闲比例;二者不能互相替代。

## 判绿:`grep -c sorry` 为 0 不等于证明成立

elaborate 失败时 Lean 可插入 `sorryAx`,因此源码中 `sorry` 计数为 0 不能证明构建成功。
编译读数(采集时点:2026-09-11):模块 125 行、`sorry` 计数 0,`make lean` EXIT=2,
定理的 axiom 闭包含 `sorryAx`。
判绿只认构建退出码;`make lean-report` 会打印 axiom 闭包,出现 `sorryAx` 即未证完。
