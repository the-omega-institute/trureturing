
## PR body and audit-comment rules (binding)
1. **Declaration identities.** Every "GID + `statement_id`" pair in an audit comment or a PR-body table is the **declaration's** `statement_id`, from the Freeze event's `declaration_statement_ids` on the immutable baseline (`origin/dev`). Generate the pairs by script. A module pin (`Golden/Frozen/state/<module>.lean.json`) is a different identity; if one appears, label it "module statement_id".
2. **Frozen prerequisites.** "Direct frozen dependencies" lists only owners whose pin already exists on `origin/dev`. Modules first frozen in the same delivery are same-delivery content and are labelled so.
3. **Readings.** Give one row per check, holding its final reading at the delivered head. In particular `make emit` is ONE row: "exit 0; a rerun reports 0 changed blueprints". There are no rows for probe, Stage A or intermediate invocations. The compile-cost table holds only delivered-head readings, plus the import-only baseline.
4. **Axiom wording.** Write "the axiom closure of every public declaration is contained in {propext, Classical.choice, Quot.sound}"; some declarations may be axiom-free.
5. **No narrative.** There are no sentences about what earlier rounds or the mirror check found or fixed, and none about freeze order (CLAUDE.md §2.10). A one-line disagreement adjudication result is allowed.
5′. **No raw command output.** Do not paste command output into the body: no `git diff --stat` listings, log excerpts or `<details>` blocks holding a transcript. State the conclusion with its command and exit code (for example "against `<rev>` the lane's source, Scribe and frozen records compare equal (`git diff --quiet … -- <paths>`, exit 0)"), and name lane-specific changed files individually. Also absent from the body: rows that record how the PR was published (`git push`, `make pr`/`pr-open`, message-file paths, bypass variables); any copy of a gate or check receipt (JSON or verbatim); compile or test readings from the probe, Stage A or any head other than the delivered head (no Phase A rows); and sentences about declarations that were deleted, renamed or merged. Before publishing, search the body for `git push`, `pr-open`, `Phase A`, `Stage A`, `probe` and `{"` and remove each hit that is not a current result.
6. **Carrier note.** If any round has a nyxid-oracle seat recorded as `not dispatched`, or a seat that ran on codex-cli as a fallback, the standing block states the result only:
   - which rounds were judged by codex-cli only;
   - review seats are verification seats, assigned to codex-cli by CLAUDE.md §5.11; nyxid-oracle takes reasoning tasks. State each round as its standing rows record it.
   - that no model-diversity claim is made.

   Do not describe the dispatch sequence (for example "dispatched only after both codex-cli seats clear a head"); review seats reject that as process narration (CLAUDE.md §2.10).
7. **Dossier Triage is complete.** The `Problems/` dossier's `## Triage` section contains every item listed under "Triage items" in the lane target, each marked proved, computed or open, with its evidence. For each computed item, re-run the computation yourself and record the command, its exit code and the script's sha256 in the dossier. State the tested scope exactly (for example "t = 2 and t = 3 at L = 9"), and mark any uniform extension beyond it as open. Reviewers reject a dossier missing any listed item. Keep experiment programs and data in the experiments repository; cite their immutable revision and path in the dossier.
8. **Mixing sentence, round-agnostic.** The provenance "Review mixing" sentence states the current layout for every round, without naming a round: "Review mixing: each round uses three codex-cli verification seats that run one after the other on the same worktree, each blind to the other seats' results within the round; every verdict counts and a reject opens a new round; no model-diversity claim is made." Do not mention a concurrent nyxid-oracle seat or describe earlier rounds.
9. **Producers exactly as preregistered.** The provenance names who surfaced the candidate exactly as the preregistration issue's "Producers" section states (for example a codex-cli search seat). Do not infer a ChatGPT Pro producer from the GoalArtifact; list a carrier only for a load-bearing output it actually produced in this delivery.
10. **Dossier at the target's exact path.** Create the `Problems/` dossier at exactly the path the lane target names.
11. **Search readings name their revision.** State the revision each repository search ran on, and keep it distinct from the delivered head; do not call either one the origin/dev tip.
12. **Cost table: delivered head only.** The compile-cost table holds the delivered-head measurement and the import-only baseline. It has no probe or Stage A rows.
13. **Identity sources.** Declaration-level `statement_id`s come from the producing Lean report (`.lake/build/stratalint/raw-lean-report.json`). The `Golden/Frozen/state/*.lean.json` record holds the module pin and the declaration name/kind list, with no per-declaration identity. Quoted Lean docstrings are labelled as Lean docstrings, not as source sentences.
14. **Each identity once.** Name the independent judgement-form and mirror seat once, in the carriers-and-roles record. Do not copy the module's comment block into the body; the declaration classification table carries it.
15. **Dossier formulas** use Markdown math delimiters (`$…$`), not plain parentheses or `sqrt` text.
16. **Provenance triple complete.** The provenance block opens with a `Skill context:` line naming the skills actually used (for example `consensus-rnd:sshx` for orchestration and `skills/codex-formalize/SKILL.md` for the codex-cli seats), or stating that none was invoked; then carriers and roles, then review mixing (CLAUDE.md §5.2). Session recovery pointers do not replace any of the three. Reviewers reject a body without the skill-context line.
17. **No verbatim gate output.** Do not paste the `make gate` JSON or its executed/skipped/deferred inventories into the body (CLAUDE.md §2.10: no receipt copies). Give the exit code and one sentence naming the diagnostics on this delivery's own paths (rule, path, admission effect), with the count of the others.

18. **Readings only for what is delivered.** No reading about an import, declaration or file that is absent from the delivered head (for example "the removed import of X has deletion exit 0"); the delivered state and its own readings carry the evidence.

19. **Standing block at first publication.** After the empty standing table, the round-1 layout line ends with: "Tally so far: 0 approve, 0 reject, 0 abstain (no round has completed). Carried-forward approvals: none. Disagreement adjudication: none." (all on that one line, which the orchestrator replaces when the round closes).
20. **Verification attribution.** The provenance block has one line "Verification attribution: …" naming what the orchestrator verified (the preregistration's source and literature checks, as recorded in the issue) and stating that every other reading in the body was measured by the implementation seat.
21. **Helper-to-consumer map.** CLAUDE.md §3.2 requires every bind-only helper (private or public) to be reported with its named live consumer. Compute the map mechanically from the elaborated proof terms (a scratch script that collects the constants of each delivered declaration's value and inverts the relation) and put a table in the PR body: helper (full name) | proof_shape | direct consumer(s). A blanket sentence such as "the remaining private theorems are bind-only helpers with live consumers" is rejected.
22. **Commands as executed.** Every reading row gives the command exactly as it ran, with variables resolved from its log (for example `BASE=<the 40-hex commit the log shows>`, not a later merge base or a placeholder), the revision it ran at, and its exit code. Before opening the PR, grep each recorded BASE/HEAD SHA in the corresponding log.
23. **Triage coverage.** Before the builder commit, map every bullet of the lane target's "Triage items" (and every computed item it names) to the dossier's `## Triage`: one row per bullet giving the dossier line, the status (proved, computed or open) and the evidence kind (kernel-checked declaration, paper argument, literature reading or computation with script, command, exit code and SHA-256). A bullet with no dossier line, a status different from the target's without a stated reason, a row that is both settled and open, or a claim marked proved that no declaration or paper argument in the dossier proves, is a defect to fix before the commit. Report the mapping in the envelope (`triage_coverage`). The PR body states each such item the same way as the dossier.
24. **Adjudication of a split round.** A completed round with any reject or abstain beside an approve is a disagreement: its tally line ends "Disagreement adjudication: the head does not clear; one objection blocks a head." (no clause about later fixes or rounds: that is chronology) A unanimous round ends "Disagreement adjudication: none (unanimous round)". Never write "none" for a split round.
25. **Dependency prose matches the proof.** Every sentence in a Lean comment, Scribe, dossier or the PR body that names a frozen or Mathlib declaration as supplying, giving or proving something must name a declaration that the delivered module imports and uses in an elaborated proof term. Check each such sentence against the imports and the helper-to-consumer map before the builder commit; mention an unused related result only as "states …; not on this module's dependency path".
26. **Tables describe the delivered tree only.** Reuse, definition, theorem and helper tables list only declarations present at the delivered head, with their current owner or reuse. No row for a deleted, merged or renamed declaration, no status such as "duplicate-deleted" or "unused adapter deleted", and no counts of "original" declarations. A reviewer reads such a row as implementation history (CLAUDE.md §2.10).
27. **Chain position (CLAUDE.md §4.7).** Before the Freeze tables, one sentence names the form: deposit-uncovered (no atom), deposit with ATOM_ID, or deposit plus cover. It also names the settling GID and how each other module is frozen (`ledger-align --add`, or an owner re-pin). The tables give the event hashes.

## Authorized mechanical fixes before the doors (binding; the only source changes allowed)
"No source change before the doors" means no change to Lean statements, proofs, Scribe formulas or prose. The following mechanical fixes are authorized when a door reports them, and you then continue without stopping:
1. **IDE0051 (unused private Scribe members).** Delete exactly the private methods or fields the analyzer names in the reported `.scribe.cs` files, and any private member used only by those members. No other edit, no analyzer suppression.
2. **Library note `claim` on several lines** (`field claim must be one canonical non-empty line`). Join it into one line holding the same text (quote it if needed) and check that the YAML parses with each backslash surviving once.
3. **Trailing whitespace or a final blank line** reported by `git diff --check` in a delivered file. Remove it.
4. **`UTILITY-SYNTAX` from a `consumer=gid:` basis** (SL-031). The grammar (repository spec A5.1) is `basis=consumer=<declaration-gid>` with a bare GID; `gid:` prefixes only `refutes=`/`terminal=` targets. Remove the `gid:` after `consumer=` in the `utility:` line. If the modules were already frozen on a local, unpushed builder commit, rebuild the freeze from `origin/dev` as for a rework (bring over the non-ledger files, never hand-edit `Golden/**`).
5. **Library note frontmatter rejected by `make emit`** (`malformed DOI`, or `field claim must be one canonical non-empty line`). Write `doi:` as a bare DOI (`10.xxxx/...`, never a `https://doi.org/` URL) or `doi: null`; write `claim:` as one quoted line (no folded `>-` or `|` block), with each backslash surviving YAML parsing exactly once (check with a YAML load). Change nothing else in the note.

If modules were already frozen or re-pinned locally in this worktree and nothing is committed, restore `Golden/**` to `HEAD` (`git restore --source=HEAD --staged --worktree -- Golden && git clean -fd -- Golden`), apply the fix, and rerun the door from `make lean-report-scoped LEAN_TARGETS="<the same list>"`; never hand-edit `Golden/**`.

## Proof-shape and utility labels in the PR body (binding)
28. **Proof shape after expansion.** Classify each delivered declaration only after inlining every same-delivery declaration: public or private, in any module this delivery freezes for the first time. Stop only at declarations already pinned on `origin/dev` or in pinned Mathlib.
    - If a declaration's live proof reaches a same-delivery content declaration, the declaration is `content`.
    - In particular, the settling `result` and its construction theorem are `content` whenever a supporting module's content lies on their path. The open-problem-resolution basis does not change this label.
    - Compute the labels in two passes:
      1. **Own step.** Mark `own-content` only for a proof that introduces a non-normalization step. Instantiation, projection, rewriting, `simp`/`ring`/`linarith`/`nlinarith`/`gcongr`/`norm_num`/`omega` after the atomic facts are supplied, `Complex.ext` splitting and applying an upstream lemma do not count. A theorem whose whole proof is `decide` or `decide +kernel` on a closed term (a certificate chunk or table check) is `bind-only`: keep it as a consumed helper and name its consumer.
      2. **Propagation.** `content` means `own-content`, or a same-delivery **content** declaration that stays on the live path after expansion (a component discarded by projection is not on the path).

      A helper that reaches only same-delivery **bind-only** helpers stays `bind-only`; over-labelling is rejected just as under-labelling is.
      3. **Bypass test** (CLAUDE.md §3.2 (iv)). A declaration labelled `content` solely through a content declaration is still `bind-only` when its conclusion can be reached from frozen or Mathlib facts and same-delivery bind-only helpers by instantiation and normalization alone. Example: a nonzeroness fact that follows from a two-line real/imaginary-part computation. An escape witness must survive this test. List, for each module, the witnesses that survive it.
    4. **Per-theorem witness.** Every row labelled `content` names its own escape witness in its `escape_witness` column, in the header comment and in the PR body: the theorem itself when its own conclusion is produced by a non-bind-only step on its live path, otherwise the intermediate proposition. A `content` row with `escape_witness: none` is rejected; module-level witness rows do not replace it.
29. **Computational utility per declaration.** A fixed-parameter numerical certificate is computational content under CLAUDE.md §3.3. This holds even inside an otherwise general module whose declarations all have live consumers. It covers a `decide` or explicit rational solve on a concrete matrix or vector, the sign of a concrete determinant, and a fixed-dimension anchor value. A module holding one never carries `utility: none`.
    - **In a supporting module,** write `kind=numeric-reduction; basis=consumer=<consuming declaration GID>; premises=<certificate declaration GIDs>`.
      - The consumer lies in a module that imports this one, on `result`'s live path.
      - The premises are fulfilled in the same delivery, with the same function, parameters, domain and threshold direction.
    - **In the settling module of a refutation,** they are certified instances under `refutes`.

## Experimental material lives in the experiments repository (CLAUDE.md §2.10 at origin/dev; binding)
Never embed an experiment program, dataset or experiment report in the main repository: not in the dossier, not in a Library note, not as a new file, and not in the PR body. Rerun instructions of the form "save the following source as …" count as embedding.

For an experiment named by the target, use its verified full commit SHA and path in `the-omega-institute/trureturing-experiments`. Resolve the local clone from the main checkout's sibling `trureturing-experiments` directory or an explicit caller input. Check the referenced script with `git -C <experiments-clone> cat-file -e <commit>:<path>` and verify its SHA-256 before citing it. A missing experiment remains unverified; do not assume it is published.

In the dossier, write one experiment entry: a link to that directory pinned to the commit, followed by the command, the exit code, the script's sha256, and the readings with their exact tested scope. The readings and the Triage stay in the dossier. If the lane needs a new or changed program, report it in the envelope under `experiment_material` (path and content); the orchestrator publishes it. Never commit to the experiments repository yourself.

## Scribe prose is mathematical exposition (binding, before the doors)
The Scribe prose describes what each declaration states and which later theorem uses it mathematically (`skills/codex-formalize/SKILL.md` Step 5). It contains no process or review vocabulary.
- Before the doors, run `grep -n -i -E "live (proof )?path|consumed step|live consumer|admission|preregist|binding|convention|designated|exempt|basis=|escape (witness|registration)|coverage|audit|bind-only|proof_shape|CLAUDE\.md|literally the" <every delivered .scribe.cs>`.
- Rewrite each match as mathematics: say what the lemma states and what uses it, and for what. Report the remaining matches, each with the reason it is mathematical.

**Evidence kinds match the Lean statements.** A Triage or body item labelled *proved* names the Lean theorem that states it. A value that Lean only bounds (for example $3 \le c_g(T)$), while the experiment computes it exactly, is labelled *computed* for the exact value and *proved* only for the bound. An explanatory identity that no Lean theorem states is described as explanation, never as "kernel-checked".

**No source code in the PR body.** Table cells and paragraphs never contain Lean source, flattened modules or program text. Point to the module path and the declaration names instead.
30. **Evidence kinds in the Triage.** Each Triage item names one evidence kind per claim: kernel-checked (name the declaration), proved in prose (write the derivation in the dossier), computed (say exactly what the experiment entry computes, and its range), or open. A family or classification beyond the kernel-checked instance is never labelled as proved in Lean, and a computation is never described as covering more than the script checks.

**Judgement table (binding, every lane).** The PR body carries one row per public theorem of every delivered module, including publicized owner declarations and consumed bind-only helpers, with these columns:
- module;
- declaration;
- `proof_shape`;
- `escape_witness`;
- consumers (for a bind-only helper);
- direct frozen dependencies, each written as the owning module's GID (file path without `.lean`) + the full Lean name + the declaration `statement_id`.

Generate the dependency cells by script from the compiled proof terms and the current Lean report; invent no address. Below the table, state each module's `admission_basis`: `escape-witness` for supporting modules, and `open-problem-resolution (#<issue>; Proved|Refuted)` for the settling module.

**SL-031 `UTILITY-SYNTAX` (canonical selectors; an authorized mechanical fix).** Every declaration reference in a `utility:` header (`consumer=`, `premises=`, `instance=`, `result=`, `claim=`, `refutes=`) is `<module GID>.<final name>`. The selector after the module GID is ONE identifier, the declaration's final name, unique within that module; nested namespace paths like `Mod.Section.decl` fail. Rewrite each to its final name after checking uniqueness. Header comments do not enter statement identity; confirm with a scoped report that every pin is unchanged.
- **No before/after readings in the body.** A fix that reports a reading "before and after" puts the before-value only in the envelope. The PR body gives the reading at the delivered head, never a comparison with an earlier build or head (for example "65 warnings before, 0 now").
- **Observation scope.** When the body counts observations, name the report they come from (`check-delta` or `check-current`), and disclose every observation the current audit reports for the job.

- **Report-cache shape.** Before the first freeze door, run `python3 tools/scripts/agent/openproblem/briefgen/purge_stale_fib.py "$(git rev-parse --show-toplevel)" --delete` and report its `PURGE_STALE_FIB` line. The tool removes cached per-module reports with an invalid `fib_analysis` shape. If a freeze door reports `fib.invalid_partition`, rerun the cleanup and retry the door once.
