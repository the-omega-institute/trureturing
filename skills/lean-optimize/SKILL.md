# Lean 性能优化

## 安装与真源

`skills/lean-optimize/` 是本技能的唯一真源。仓库的 `.codex/skills` 和 `.claude/skills` 目录链接共同发现此副本；其他安装只能作为它的投影，不另行维护独立副本。

以可复测的时间、内存或重编范围改善为成果，保持原数学结论、适用范围和允许的公理闭包。优化对象可以是证明、可执行检查器、模块依赖或构建使用方式；先定位实际成本，再选路线。

## 适用范围与入口

- 用户只问进度、原因或方案时，先做只读诊断；不为回答状态启动编译、重写证明或安装工具。
- 用户要求实施优化时，在授权范围内完成修改、对照和验证。遵守目标仓库的 AGENTS、工作树、缓存、生成物及冻结规则；本技能不扩大发布、终止其他任务或修改验证器的权限。
- 在 trureturing 中，先读 [仓库适配](references/trureturing.md)。其他项目使用其现有构建与验证入口，不套用该仓库的命令。
- 定位到证明或有限检查器后，按需读 [优化路线](references/techniques.md)。

## 先辨认正在花费什么

沿目标进程的父子链核对启动命令、实际 cwd、工作树、开始时间和日志。区分正在编译、等待构建锁、缓存准备、报告提取、下载与消费检查，不把 wrapper 的存活当作编译进展。

读取当前源码提交、toolchain pin、依赖锁文件、目标模块、缓存恢复记录和实际重编模块。缓存标为 warm 只说明入口定义的探针通过，不保证所有模块的构建 trace 有效。缺少 `.olean` 的数量只能报告为缺产物数量，不能当作精确剩余任务、完成率或预计时间；已有产物也可能失效。

根据证据选一个当前瓶颈：

| 信号 | 要查的证据 | 下一步 |
| --- | --- | --- |
| 目标还没进入 Lean | 锁等待、恢复/下载阶段、父进程与退出状态 | 处理准备路径，不先改证明 |
| 很多无关模块重编 | pin、编译选项、imports、生成源码及失效 trace | 缩小受影响闭包，恢复兼容缓存 |
| 单个声明计算昂贵 | 该声明的 profiler/受控编译与内核检查成本 | 比较证明策略或检查器结构 |
| 多进程长时间运行 | 两次采样的 CPU 时间增量、CPU idle、内存压力与 swap 变化 | 受控比较并发，不凭 elapsed 或 swap 存量定因 |
| Lean 已结束但任务未结束 | 报告器、注册、消费者检查和原生退出码 | 优化实际剩余阶段 |

只诊断时，给出读数、可定位的原因、尚未测量的部分和下一项能区分解释的检查，随后结束。不将候选方案写成已经验证的加速。

## 建立可比较的基线

先在当前会话固定：原目标、最小代表性模块/声明、要改善的成本、可接受的资源范围和成功判据。不要默认承诺固定倍数。

记录影响可比性的条件：源码版本与差异、Lean/依赖版本、精确命令、构建目标、缓存状态、并发、机器资源以及同机其他负载。对已经完成且输入条件匹配的测量可以复用；旧日志不能冒充当前源码的验证。

区分三种测量：无改动的缓存复用、依赖已热但目标真实重编、完整恢复/构建。按用户的成本目标选择，前后保持同一种口径。基线和候选都要确认实际执行了被优化的证明；一次缓存命中不能与一次真实编译比较后宣称证明更快。

优先使用已有的单目标重编或 profiling 入口。若暂不能安全地使基线与候选真实重编，就报告该比较尚未建立，不清空共享缓存来制造基线。不要借测量启动整库冷编译。除非明确需要全量验证，否则保持定向范围；确需全量时先说明必要性，每条全量或间接触发全量的命令显式传入确认参数（trureturing 使用 `FULL_BUILD=1`，具体入口见仓库适配）。

收集成功退出码、墙钟时间、进程及其子进程的 CPU 成本、峰值内存；共享机器上同时采集 CPU idle 和内存压力。使用操作系统支持的计时/profiler 工具，并说明单位和覆盖范围。抽样 RSS 是当前驻留量，不是峰值；相加的进程 RSS 不等于去重后的物理内存。heartbeats 是诊断读数，不是跨策略的统一时间单位。

## 从小对照推进到实际消费者

先搜索本仓、钉版 mathlib 和可准入上游，复用已有证明与检查器接口。不要为省实现时间重证已有结论，也不要为了性能统一重命名或拆分无关模块。

一次针对一个明确成本来源修改。先选单行、单块或单声明作有界试验，再选有代表性的完整目标，最后验证实际受影响消费者。小样本加速只支持该样本，不代替完整证书通过；调大 heartbeat、recursion 或 timeout 只是资源调整，不能报告为计算量下降。

战术替换、数据布局、分块粒度、算法与并发均为候选，先从钉版实现确认能力。不要将 `decide_cbv`、`cbv`、`simp` 或任何 tactic 列为无条件更快的默认答案。若连续两次受控尝试没有改善目标成本，重读瓶颈与 profiler，换优化层次；不原样增加预算。

跨工作树的缓存恢复、模块重编和验证可能写文件；按项目隔离规则操作。长任务用宿主可追踪的作业句柄，获取真实结束状态。只管理本任务有归属凭据的进程，不能因它与当前构建争资源就终止其他会话。

## 保持数学与信任边界

对比优化前后的完整声明：所有参数、类型类、量词、假设、域、边界情形、数值输入与结论都要保留。修改定义还要核对依赖该定义的语义和消费者，不能只比较定理名称或显示后的短类型。

算法优化可以改变内部表示与遍历顺序，但必须给出到原完整命题的 Lean 证明。预分组、对称约化、基表示和压缩证书各自有覆盖、保持性或还原义务；不能用抽样、缩小域、跳过困难数据或另一个较弱命题换取提速。

检查当前编译结果的公理闭包，并核对仓库允许的边界。`native_decide`、`decide +native` 以及调用本机求值的 SAT/位向量策略不能仅凭名称当作纯内核路线；读取钉版实现与实际闭包。外部计算若参与搜索，最终采用的结果仍须通过边界内的证明或有 soundness 证明的证书检查器验证。拒绝 `sorry`、新增私有 axiom、跳过消费者或放宽判官来换取绿灯。

## 验证与交付

先完成目标与相关消费者的编译，再用项目现有工具核对精确类型、公理闭包及要求的生成物、冻结与准入检查。只改证明也可能改变冻结身份，交给现役 writer 处理，不能手写状态或假设无需重钉。

性能结论与正确性结论分开报告。候选编译通过但尚无公平测量，只能称正确性验证通过、性能未验证；性能改善但完整目标未通过，不算完成。必要时少量重复同口径测量，给出原始读数和范围；输入与负载足够稳定后，不为堆次数反复跑昂贵构建。

最终提供：改动位置、保持了什么、前后成本与比较条件、真实检查结果、内存/证明体积/消费者构建等取舍和未解决边界。没有可接受的改善时，撤销本次无收益且无其他价值的修改，保留既有用户工作及有价值的诊断结果。持久材料只保留项目允许的源码、可复用实验与结果，不建立逐次尝试日记或回执副本。
