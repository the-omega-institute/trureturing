# Lean 优化路线

只读取与已定位瓶颈有关的部分。下列路线均须经同口径测量选择，名称或算法复杂度不能代替实际编译成本。

## 求值型证明

先区分元层求值、证明项生成和内核验证。一个 tactic 可以在元层很快算出答案，却留下内核仍需重新展开的大项；另一个可以生成很大的显式证明，节省归约却增加内存、产物和 import 成本。对照应覆盖完整目标编译，不只覆盖 tactic 内部计时。

- 在钉版中确认 `decide +kernel`、`decide_cbv` 和 `cbv` 的可用性、导入与实际实现。先用同一个完整小目标比较它们，不假定全部版本都提供这些入口。
- 使用 `simp only`、定向改写与可复用的已证引理消去重复推导时，同时测量展开、实例搜索和内核检查成本。把定义移入 `let` 或新 helper 不自动保证运行时或归约共享。
- 对每次替换核验公理闭包。即使 tactic 返回一个 proof term，也要确认它没有引用新增本机求值 axiom；`bv_decide` 等策略同样适用。
- 已知的中间事实可提取为有真实消费者的辅助声明。避免生成大量仅用于缓存、展示或登记的无消费者包装；遵守项目的 bind-only 规则。

## 有限枚举与证书检查

先找工作量是否来自候选搜索、证书验证、重复表查询、重复子问题或表示转换。编译时不必重新运行搜索；可以用外部程序寻找证书，再用有 Lean soundness 证明的检查器核验它。保留来源、输入与项目要求的证书身份。

常见结构改写：

| 改写 | 节省的候选成本 | 必须补齐的证明 |
| --- | --- | --- |
| 按颜色、标签或不变量预分组 | 排除无关组之间的扫描 | 每个原对象都进入正确组，所有相关对仍被检查 |
| 位集替代逐元素谓词 | 把成员/交并/包含检查批量化 | 位宽、截断、零元素、编码及解码保持原谓词 |
| 基或生成元替代遍历全空间 | 将全称检查移到生成结构 | 基的有效性、生成完整性、所需性质的线性或闭包保持 |
| 对称群轨道代表 | 合并等价输入 | 作用合法、代表覆盖、目标与操作在作用下保持 |
| 预计算共享表与子证书 | 复用重复推导 | 表项正确、覆盖全部查询，消费者依赖实际使用该证据 |

这些是对原结论的证明组织，不是缩小验证范围。若某种改写只验证较强的充分条件，也必须证明它推出原完整命题，并让当前数据实际通过；不必为了声称优化而强求双向等价。

分块比较要同时考虑总 CPU、最大块成本、峰值内存和调度开销。块变小可能改善内存和进度可见性，也可能增加重复导入、元数据和汇总证明。不要只看文件数量。正交性、覆盖和颜色检查可能有不同瓶颈，可按实际依赖拆开，保持全部证据被完整汇总消费。

## Elaborator、实例搜索与化简

使用钉版支持的 profiler 找到实际高成本声明、tactic 或实例搜索。优先补充必要类型和局部实例、缩小自动搜索、限定化简集、避免循环改写与反复展开大型定义。没有证据时不要全仓补类型或清理 imports。

减少 tactic 搜索不一定减少内核成本。对生成证明项体积、目标重编时间及消费者导入成本一起比较；避免把昂贵步骤藏入透明别名后反复归约。

## imports、缓存与并发

将只依赖小接口的模块改为窄 import，或隔离大型常量表时，验证语义、实例可见性和消费者，测量实际重编闭包。模块拆分可能改善缓存粒度，也可能扩大导入成本，不能仅凭层数判断。

缓存比较保持 Lean、依赖、源码与编译选项身份。复用由项目入口和 Lake trace 判定，不能伪造 trace、touch 输入来隐瞒变化，或从另一版本随意复制 `.olean`。成功缓存复用是构建改进，与首次检查器加速分别报告。

区分单个 Lean 进程的线程数、Lake 同时运行的编译器数量和多会话构建数量。先核对钉版实际支持的调度参数；不能把 `lean -j1` 当作全局只编一个模块，也不能凭印象使用 `lake -j` 或某个环境变量。

对并发只提出可验证的假设：例如相同目标下，降低同时运行的重型模块是否改善墙钟、内存压力和 swap 增量。控制基线与候选的并发及外部负载，得到读数后决定。swap 存量、load average、进程 elapsed 或一次 CPU 百分比都不能单独证明过载、死锁或剩余时间。
