# 追加批次骨架(APPEND.md)

把下面「骨架」整段**追加到卷文件末尾**(在既有的追加锚之后),换掉占位符,**不动文件里已有的任何一个字节**。
每批以一行新的、与既有锚**逐字相同**的追加锚结尾——那一行是下一批的落脚点,漏写即破坏本卷的追加性质。

## 三条硬纪律

1. **首行必须是 heading。** 追加块的第一个 Markdown block 必须是 `## <编号>. <标题>`。
   只有这样,上一批留下的追加锚才保持「只有标题行」的形态而被消化器丢弃;
   若第一个 block 是段落或表格,那个锚会变成一个 atom,下一批再追加时它的字节就会变。
2. **编号只增,永不复用、永不重排。** 章号接着卷内最大章号往下走,定理号写作 `<章号>.<序号>`。
   编号唯一 ⟹ 地址唯一 ⟹ 新增内容不可能撞上既有 atom 的地址。
3. **不回头改字节。** 勘误的形式是在本批里点名旧编号并给出改判,旧章原样留着。
   改一个字都会让那条 atom 的指纹变化,消化器把它读成「旧 atom 消失、新 atom 出现」。

## 骨架

新增公式遵守 [SKILL.md 的 GitHub 公式规则](SKILL.md#github-公式)。下面的块级公式是可选位置，按实际命题替换或删除。

```markdown

## <N>. 增补<批次序数>·<本批主题>

**本批导航。** 本批在 <基线或上一批的 commit/PR> 之上增补:§<N> <一句话>、§<N+1> <一句话>。
本批**扩充/限定/改判**了 §<旧章> 的 <旧编号>:<改判内容,或写「不改判既有条目」>。
基线叙述中的「本次」「本轮」仍指写下它的那一次工作,本批不改写它们。

**定理 <N>.1（<名>）。** <完整陈述。>

$$
\text{<替换为本定理的实际数学结论>}
$$

**证明。** <证明正文。>

**命题 <N>.2（<名>）。** <陈述。>

**证明。** <证明正文。>

## <N+1>. 本批的来源、边界与核验

**文献表态。** <literature-attested 的逐条范围 / repo-derived / suspected-novel;第 3.7 条。>

**产地。** <skill 上下文 / 载体与分工 / 混合方式;第 5.2 条三项,写实。>

**本批不主张的。** <本批没有验证、没有形式化、没有覆盖的东西,逐条写明,不用含糊句。>

## 追加锚（本行以下为增补区）
```

## 落地判据

在同一会话工作树核对该卷的 Git diff，确保只追加正文，然后运行
`make ingest SOURCE=<source-id 或卷路径>`。摄入须退出 0 且
`coarse_fallbacks=0`，生成写集只新增 ATOM 与必要的 source metadata。

用 `make search-atoms SOURCE=<source-id> TEXT=<新增命题关键词>` 找到新增内容，
再用 `make show-atom` 核对其文本。不要以全卷条目计数或全账本检查代替正文
和新增 ATOM 的对应检查。
