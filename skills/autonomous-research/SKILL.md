# Autonomous Research Round

## Scope and authority

This file packages a research selection and continuation workflow; it has no authority of its own. `docs/develop/spec/golden-ledger-repo-spec.md` is the sole normative specification; `CLAUDE.md` is the invariant frame governing how work is done; and `agents/CONTEXT.md` is the finite-context map and routing aid. Live harness output is the decisive judge of fact about the current tree. If this file disagrees with any of them, they win and this file is the bug.

Complete one bounded round: observe, select or report idle, preregister, execute through the existing owner, settle, reason about the result and propose the next candidate. The session is a temporary executor; the repository's results and unresolved boundaries carry continuity. This skill supplies no session startup, scheduler, new admission gate or human-review gate. Its value policy chooses research attempts; it is not `admission_basis` and does not change `CLAUDE.md` §§3.2–3.3. A valuable application or surprising answer does not authorize an otherwise inadmissible new declaration.

Read `CLAUDE.md`, `agents/CONTEXT.md` and the applicable owner below before execution. Use the current goal and actual harness capabilities, rather than inheriting a template's goal or claiming a tool result from its documentation.

## 1. Observe and bound the round

Fix the round's time/resource budget, deadline and stopping conditions before searching. For a continuing research line, bound this round's contribution without replacing the line's preregistered success and stopping criteria with an hourly deadline.

Observe the current branch, immutable base, working changes, in-flight PRs and CI, open preregistration issues, `Problems/` dossiers, `Library/`, existing `D5/` results and relevant research-line obstacles. Use `git status --short`, `git rev-parse HEAD`, `gh pr list --state open`, `gh issue list --state open --search 'Preregister in:title'`, and the selected PR's `gh pr checks <number>` as applicable. Check query limits/pagination before claiming an exhaustive screen. Unavailable queries are named missing readings, not empty work queues. Respect other worktrees and live workers under `CLAUDE.md` §§5.11, 6.1.

On entry, including in a new session, inspect the existing preregistration issues and research-line records within the current goal and authorization in this order: recover unsettled units first, screen registered successors next, and generate new candidates only when neither supplies an eligible unit. Include closed issues when discovering successors: use `gh issue list --state all --search 'Research unit in:title'` and `gh issue list --state all --search 'Preregister in:title'` as applicable, read relevant issue bodies and all comments with `gh issue view <number> --comments`, and follow their result and research-line links. A successor is an input to the screening in §2, not an accepted assignment. Failed or incomplete reads do not establish that any of these sources is empty. Record each missing reading or capability and its dependent candidates/sources and work under §5.9 in the existing preregistration issue or research-line record, or the round report if neither exists; block only dependent work and continue screening independent candidates or sources within the same round budget and deadline. A selection gap stops the round only when all remaining work that could advance within the stated bounded search scope depends on that gap; report the scope, dependency and unresolved candidates as incomplete selection, distinct from idle. The fixed deadline, resource limit and registered stopping conditions still apply.

Before resuming an unsettled unit, reconcile its preregistration and comments with the actual branch/base and working changes, linked PR state and head, CI for that head, registered deadline/resource limits and stopping conditions, and available authorization/capabilities. Check for existing solver/evaluator results and live workers before taking over. Resume only the remaining work under the original criteria; reuse completed work whose evidence and inputs remain current, and do not reset predictions, execution start or deadline. If the deadline or a stopping trigger has already been reached, settle from existing evidence under §5 rather than starting the attempt again. Missing evidence remains unresolved; it is not a negative mathematical answer.

Determine whether a unit has ended from its terminal or owning route's settlement evidence, not merely the issue's open/closed flag. An ended unit, including an invalid or unresolved terminal, is not resumed or solved again and receives no second terminal or altered prediction. If the result is settled but its required reporting is incomplete, finish only that reporting without duplicating an existing terminal. Continuing an ended question requires a fresh preregistration citing the old result and preserving its conclusion and boundaries.

Reuse prior results first. Search repository declarations, including private ones, then pinned Mathlib, then admissible third-party Lean libraries in the order of §3.1; check literature and in-flight work for duplicates and stronger results. Compare statements, assumptions, quantifiers and actual consumers, not just names or import counts. Do not assign implementation for an already solved target or create a wrapper to count it as new work.

## 2. Generate and screen candidates

Candidates can come from a shared proof mechanism awaiting generalization, a bridge between domains, a hypothesis or bound needing a sharpness test, independently predicted disagreement, an unknown registration residual, an unresolved `## Triage` item, two observationally indistinguishable implementations with different target answers, or incompatible conclusions whose common assumptions need checking. An unknown residual is a question source, not proof that a new theorem exists. For physical candidates, distinguish a model consequence from empirical truth and identify which model premises are proved, assumed or outside Lean.

For sharpness/boundary sources that need declaration-level users, use `make -s -C tools compiled-dependencies` with the fixed revision and explicit finite module domain described in `tools/scripts/agent/research_readouts/README.md`. The entry acquires compiler artifacts through the existing make/cache doors and separates type/constructor, raw proof/definition value and module-import edges, including forward/reverse paths and completeness. Keep its domain and acquisition status with the reading; missing/incomplete data is unmeasured, never an exact zero. Private/internal intermediates carry paths without adding public users. Raw value occurrence only screens sources: it is not the reduced live-path test of §3.2, indispensability, an escape witness or research value. A finite query does not establish a whole-D5 ordering.

For each serious candidate, identify its source, fully quantified statement, relation to existing work, the specific statements affected by a yes/no answer, intended consumers, missing inference or realization bridge, estimated cost and appropriate route. These are working inputs, not a new question-card schema or ledger. External candidates additionally need the verbatim published named question, tier and scoped literature readings required by §3.6. Internal candidates, including descendants of external settlements, cannot use `open-problem-resolution` merely because they have been written as a question or placed in a dossier.

Use this research selection policy:

- **Structural value:** seek both (i) a result difficult to obtain from the current library, or an answer that independent preregistered predictions cannot already settle, and (ii) concrete other statements made easier to obtain by that result. Distinguish value in discovering an object, choosing a model and proving model premises from novelty in the eventual proof term. These distinctions never change `proof_shape` or admission.
- **Threshold 0 — irreducibility:** preregister a cheap probe and its budget, then try library reuse, direct binding/normalization and a small search where relevant. A candidate survives this threshold when that probe cannot solve it within budget. Probe failure is a bounded observation, not proof of difficulty. A solved probe is reported honestly and routed under existing rules; it does not justify manufacturing a harder variant or more implementation work.
- **Six coordinates:** assess the following separately. Candidate-stage expectations must remain distinct from settlement evidence. A missing coordinate is unmeasured, not zero. The coordinates are not six conjunctive admission requirements.

| Coordinate | Evidence sought |
| --- | --- |
| Generativity | At least two independent concrete consumers made cheap by the result; measure the resulting derivation or proof-length savings; consumers must actually use it on a live derivation path. Imports alone do not count. |
| Connection | A newly connected pair of previously disconnected domains, with actual consumers on both sides. Similar notation is insufficient. |
| Sharpness | Compiled counterexamples after removing hypotheses, or an attaining example for a bound; state the fraction of hypotheses tested and the remaining scope. |
| Discrimination | Independent model-family answer/probability predictions made before probing/solving, with disagreement or lack of unanimous high confidence. Prediction seats do not solve the unit. Report the actual family diversity. |
| Generality | At least one genuinely removed hypothesis or one additional semantically different nontrivial class relative to the strongest known result. |
| Continuation | At least one ensuing question that independently survives threshold 0 and the discrimination screen; an untested suggestion is only a candidate. |

Mark as zero value for selection: a bind-only answer already confidently predicted; restatement or renaming; an isolated finite computation without family consequences; a hypothesis containing the conclusion; a constant chosen to force the answer; or a result with no consumer, connection or sharpness. These are research selection judgments, not new machine verdicts or exceptions to §§3.2–3.3. In particular, the external named-problem exception remains governed by §3.2 even when its proof is bind-only.

Compare candidates by coordinatewise weak dominance where evidence is comparable. Do not synthesize a value total. An optional ordering proxy may use independently estimated success probability, prior disagreement, linked statements affected by either answer and cost; it only chooses the order of attempts. Do not compute a proxy from missing inputs or treat it as evidence of value. No exploration quota or value-function choice is implied by this skill.

## 3. Preregister probes and choose one unit

Before a mathematical probe, fix its statement, assumptions, budget and stop test; preregister the proposed non-binding fact where §3.2 requires an escape witness. For an external named problem, its issue must already contain the verbatim source, full statement, tier and literature checks before the probe, including a probe that could settle it. Prediction seats submit their answers and probabilities before seeing probe or solver output. Assign proposer, predictor and solver to different seats, with an independent evaluator; no seat evaluates its own proposed question. Oracle seats may reason or predict but never validate.

After both independent predictions and budgeted threshold-0 probes are complete, apply §2's selection policy before choosing or dispatching a research unit for substantive solving. Route zero-value candidates and answers already obtained by a probe through the existing reuse/settlement owner in §4, without dispatching them as research units. High confidence alone does not establish bind-only proof shape; unknown shape remains unmeasured, and the six coordinates are not conjunctive gates. After two consecutive bind-only targets outside the external exception, follow §3.2 and change representation or topic before choosing another unit. Choose one surviving unit only after its required checks are complete; a gap annotation does not complete them. If completed screening finds none qualifies, report idle only after each encountered atom has a route outcome or named blocker; list excluded candidates with that result, preserve any useful result in its existing owner, and stop the round without filler Lean or an idle-state file. Failed reads or missing capabilities follow §1's candidate/source scope and round stopping rule, not an empty queue or a completed screen.

When this screening uses digestion, `codex-formalize` owns the encountered set: every atom returned or examined by the search, every context or child atom actually read, and every rejected or unsuitable candidate. Before choosing a surviving unit or reporting idle, route each encountered atom through its existing canonical cover, settle, decompose, or deposit path. A bare recommendation, skip, defer, or unexecuted handoff does not process it; unsuitability alone never proves a proposition or licenses a nonpropositional settlement. A genuine mathematical gap or missing writer outcome is a named unresolved blocker with concrete next handling and prevents claiming that all encountered atoms were processed. This set is limited to the current selection and is not a global backlog sweep. When no digestion is used, the ordinary one-unit selection route remains unchanged.

Before substantive solving, complete the preregistration with success, refutation and stopping criteria; falsifiable predictions and their owners; exact deadline/resource limits; affected statements; intended proof shape, escape witness and admission basis; literature scope; and separated seats. Use the existing preregistration issue or research-line record, not a new store. Describe a changed target or witness in a fresh preregistration before further probes; never retrofit a prediction or overwrite an old settlement. Preregistration, prediction ownership and execution are distinct even when they share a record. For machine-recomputable prediction readings, use the unchanged preregistration-comment block in `tools/scripts/agent/research_readouts/README.md`: fix the quantified binary event, seat/model-family probabilities, binary Brier rule/version, surprise threshold and deadline before substantive execution. The registration stamp comes from the carrier, not a later payload edit.

When consuming a registered successor, cite its source unit/result and exact candidate in the new unit's normal preregistration. Recheck current results, duplicates, threshold 0, discrimination, admission and use under §§2–3; a predecessor's screening or value judgment does not transfer automatically. Keep continuity references, results/boundaries and successor text outside the strict `research-prereg-v1` and `research-terminal-v1` JSON blocks documented in `tools/scripts/agent/research_readouts/README.md`; use those blocks unchanged, without extra fields or edits to prior blocks.

| Work | Owner and entry |

The openproblem operational documentation and templates remain subordinate to current `CLAUDE.md`. Its `tools/scripts/agent/openproblem/gen_review.py` requires an oracle validation seat, so do not invoke it for review. Use the current §5.11 sshx layout with all validation, including form/fidelity, architecture, quality and tests, on codex-cli; oracle only reasons. Do not run a downstream path that regenerates an oracle review assignment. Check other pipeline helpers' actual contracts before using them; do not inherit a fixed GoalArtifact from `tools/scripts/agent/openproblem/templates/impl-base-brief.md`. Reuse applicable stages with the actual unit's target and authority intact, without copying or rewriting the pipeline here.

Run within existing worktree, publication and machine-check contracts. This skill does not expand authorization for other branches, external writes or private experiment storage. A real authorization/capability gap is reported specifically; no additional human-review gate is introduced.

## 5. Settle and reason forward

At the deadline or a registered stopping trigger, settle the unit using the preregistered criteria and the existing local-settlement vocabulary of §2.7. Separate proved/refuted claims, invalid attempts and unresolved obstacles; an incomplete run does not prove either answer. An unresolved long-line substep keeps its line's broader criteria. Record actual checks and their scope; local success is not remote required-CI success, and publication is not merged delivery.

Then perform §3.6's post-settlement reasoning in an existing external problem dossier's `## Triage`, marking each statement proved, computed or unresolved. `Problems/` accepts only questions explicitly posed by external literature authors, with a resolvable bibkey and matching DOI/URL under spec §11.20.3. Keep internal candidates' results and boundaries in their existing research-line or formal-result owner; do not create an internal `Problems/` dossier or a second store. A refutation should explain the failed mechanism, missing condition, surviving weaker forms and effects on dependent claims. A proof should identify its mechanism or invariant, potential generality, tightness and neighboring applications, and the effects on dependent claims. Keep this as mathematical results and boundaries, not a session narrative.

For every non-idle round, retain the necessary mathematical conclusions, unresolved boundaries and an exact successor candidate in the unit's original preregistration issue or existing research-line record. Include links to the source result/evidence, the fully quantified successor statement and assumptions, and the checks still needed; if no successor was identified, state why, including any missing readings. Keep formal results in their existing owner and link them rather than duplicating them. New candidates require their own screening, preregistration and admission basis; proposing one does not start another round. This existing carrier is the next session's discovery source; do not add a candidate store, global index or latest pointer. For idle rounds, report the search scope, exclusions and next useful search direction or its absence without inventing a mathematical settlement, dossier edit or main-repository state file. Distinguish a completed screen with no eligible candidate from an incomplete screen due to failed reads or missing capabilities; report the latter as a named gap, not an empty queue or completed selection.

## 6. Evidence limits and retained output

For prediction scores and five-mode readings, use `make -s -C tools research-readouts ISSUES="<issue numbers>" AS_OF="<UTC cutoff>"` or the stdin snapshot route in `tools/scripts/agent/research_readouts/README.md`. The implementation is `tools/scripts/agent/research_readouts/readouts.py`. Append its unchanged terminal block with the recorded execution start and existing settlement/§3.2 evidence; let the tool recompute scores and modes. Report all five counts, X/Y/Z, denominators, scoring/mode coverage and missingness. A missing prediction never yields y; an unresolved answer is never scored as false. Distinguish structural zeros under z=1 from measured surprise, and do not backfill historical probabilities. The arithmetic checks references and recorded timing; the owning evaluator still checks mathematical fidelity, live-path shape and seat independence. Brier scores measure prediction error, not research value or mathematical information. Residual sufficiency (`residual_sufficiency`) and a registered value function f remain **未取得/未测**; do not infer them from this command, calculate E[f] or a ranking, or automatically adjust source quotas. A qualitative discrimination judgment does not establish calibration.

Retain only formal results, necessary source/literature evidence, conclusions and unresolved boundaries in their existing owners under §2.10. Experimental programs, data and reports belong to the private experiments repository under its actual write authorization. Do not add probe programs, question-card stores, aggregate scoreboards, review transcripts, command streams or receipt copies to the main repository. Do not commit aggregates (§4.5); compute legitimate summaries on demand. The session's ephemeral working notes are not deliverables.

Report the chosen unit or idle outcome, what was solved or remains unresolved under the registered tests, the essential evidence and limits, affected existing results, where any retained result landed, and the next candidate or its absence. Distinguish research progress, verified mathematical truth and delivery state.
